# HireD Driver App & Backend Database Integration Audit

## 1. Table Classification (Strict Scope Protection)

Every PostgreSQL table is classified into one of four categories to guarantee that the Admin Portal and B2B Portal remain 100% unaffected.

| Table Name | Prisma Model | Classification | Driver App Access | Scope Rule & Safety Guard |
|---|---|---|---|---|
| `drivers` | `Driver` | **SHARED** | Read profile, update online/offline duty, update photo | Existing columns and admin management remain unchanged. |
| `driver_documents` | `DriverDocument` | **SHARED** | Upload KYC, view own uploaded docs & signed links | Existing admin review and verification untouched. |
| `driver_leaves` | `DriverLeave` | **SHARED** | Create own leave, delete own leave, list own leaves | Additive `status` (PENDING, APPROVED, REJECTED) & `reason`. Existing rows backfilled to APPROVED. Admin query untouched. |
| `driver_locations` | `DriverLocation` | **DRIVER** | Full Read/Write (UPSERT single ping) | Dedicated live tracking table. Latest point per driver. |
| `driver_location_history` | `DriverLocationHistory` | **DRIVER** | Full Write (Append single & batch pings) | Dedicated audit breadcrumbs table. Indexed on `[driverId, recordedAt]`. |
| `orders` | `Order` | **SHARED** | Read-only (pickup/dropoff, times, contact info) | No writes from driver. Admin/B2B creation & status lifecycle untouched. |
| `order_items` | `OrderItem` | **NOT NEEDED** | Not needed by driver app | User decision: order items not used. Excluded from schema & responses. |
| `trips` | `Trip` | **SHARED** | Read assigned trips, start trip (selfie), close trip (OTP) | State transitions strictly forward (`ASSIGNED` → `ONGOING` → `CLOSED`). Admin pricing and reassignment untouched. |
| `expenses` | `Expense` | **SHARED** | Create, update, delete expenses while trip is ONGOING | Only editable while trip is active. Immutable once closed. Admin audit intact. |
| `trip_payrolls` | `TripPayroll` | **SHARED** | Read-only indirectly via wallet | Generated by backend during trip close transaction. Invoicing rules untouched. |
| `driver_wallet_transactions` | `DriverWalletTransaction` | **SHARED** | Read-only ledger & calculated balance | Payout credits generated on trip close. Admin offline debits untouched. |
| `offices` | `Office` | **SHARED** | Read-only (Head office contact info) | No driver writes. Head office queried (`ORDER BY office_id ASC LIMIT 1`). |
| `audit_logs` | `AuditLog` | **SHARED** | Append-only (Backend writes driver audit rows) | System-wide audit trail. Writes `actorType: DRIVER` on state-changing actions. |
| `sessions` | `Session` | **SHARED** | Create on login, rotate on refresh, revoke on logout | Dual-token authentication with refresh token hashing. |
| `password_setup_tokens` | `PasswordSetupToken` | **SHARED** | One-time password setup | Onboarding verification. |
| `companies` | `Company` | **ADMIN / B2B-ONLY** | Untouched (Trip joins company name for driver display) | No driver routes or schema modifications. |
| `admins` | `Admin` | **ADMIN-ONLY** | Untouched | Staff identity. Never accessed by driver app. |
| `invoices` | `Invoice` | **ADMIN / B2B-ONLY** | Untouched | Financial billing statement & 2-admin verification. Driver never touches. |
| `notifications` | `Notification` | **ADMIN / B2B-ONLY** | Untouched | Partner email dispatch ledger. Driver does not touch. |
| `company_registration_requests` | `CompanyRegistrationRequest` | **B2B / ADMIN-ONLY** | Untouched | Partner onboarding queue. Driver does not touch. |

### C. CHANGES MADE: Files, Routes, Migrations

1. **Database Schema & Migrations**:
   - `backend/prisma/schema.prisma`: Added `DriverLocation`, `DriverLocationHistory` models; added `status` and `reason` fields to `DriverLeave`.
   - `backend/prisma/migrations/20261019104000_add_driver_locations_and_leave_status/migration.sql`:
     - Added `status VARCHAR(20) NOT NULL DEFAULT 'PENDING'` with check constraint and backfilled existing rows to `'APPROVED'`.
     - Added `reason VARCHAR(500) NULL`.
     - Created `driver_locations` table (`driver_id` PK, GPS coords, telemetry, `updated_at`).
     - Created `driver_location_history` table (`id` BIGSERIAL PK, `driver_id`, `lat`, `lng`, `speed`, `recorded_at`) with index on `("driver_id", "recorded_at")`.
2. **Backend API Endpoints**:
   - `backend/src/routes/driver.routes.js`: Added driver-facing routes with `authenticate(['DRIVER'])` middleware.
   - `backend/src/modules/driver/driver.controller.js`: Added handlers for office, leaves (create, list, delete), expenses (create, list, update, delete, confirm), wallet, live location ping, batch offline locations, photo upload.
   - `backend/src/modules/driver/driver.service.js`: Implemented business logic, data isolation (`where: { driverId }`), audit log recording, and rate limiting (3s throttle).
   - `backend/src/server.js`: Added `/health` and `/api/v1/health` DB check endpoints.
   - `backend/src/seed.js`: Seeded test office, partner company, drivers with known password (`Driver@123`), assigned trip, and wallet credit.
3. **Automated Test Suite**:
   - `backend/tests/driver_app_endpoints.test.js`: Added 20 end-to-end integration tests covering authentication, data isolation, lifecycle transitions, expenses, leaves, rate limiting, and wallet calculations.
   - `backend/package.json`: Added `test:driver` and integrated into `npm test`.
