## 1. Table Classification (Strict Scope Protection)

Every PostgreSQL table is classified to guarantee that the Admin Portal and B2B Portal remain 100% unaffected.

| Table Name | Prisma Model | Classification | Driver App Access | Scope Rule & Safety Guard |
|---|---|---|---|---|
| `drivers` | `Driver` | **SHARED** | Read profile, update online/offline duty, update photo | Existing columns and admin management remain unchanged. |
| `driver_documents` | `DriverDocument` | **SHARED** | Upload KYC, view own uploaded docs & signed links | Existing admin review and verification untouched. |
| `driver_leaves` | `DriverLeave` | **SHARED** | Create own leave, delete own leave, list own leaves | Additive `status` + `reason`. Admin query untouched. |
| `driver_locations` | `DriverLocation` | **DRIVER** | Full Read/Write (UPSERT single ping) | Dedicated live tracking table. Latest point per driver. |
| `driver_location_history` | `DriverLocationHistory` | **DRIVER** | Full Write (batch pings) | Audit breadcrumbs. Indexed on `[driverId, recordedAt]`. |
| `orders` | `Order` | **SHARED** | Read-only (pickup/dropoff, times, contact info) | No writes from driver. Admin/B2B lifecycle untouched. |
| `order_items` | `OrderItem` | **NOT NEEDED** | Not used | Excluded per user instruction. |
| `trips` | `Trip` | **SHARED** | Read assigned trips, start (selfie), close (OTP) | State: ASSIGNED → ONGOING → CLOSED only. |
| `expenses` | `Expense` | **SHARED** | Create/update/delete while trip is ONGOING | Immutable once closed. Admin audit intact. |
| `trip_payrolls` | `TripPayroll` | **SHARED** | Read-only indirectly via wallet | Generated by backend on trip close. |
| `driver_wallet_transactions` | `DriverWalletTransaction` | **SHARED** | Read-only balance & ledger | Payout credits on trip close. Admin debits untouched. |
| `offices` | `Office` | **SHARED** | Read-only head office info | No driver writes. Queried by `office_id ASC LIMIT 1`. |
| `audit_logs` | `AuditLog` | **SHARED** | Append-only | `actorType: DRIVER` on all state-changing operations. |
| `sessions` | `Session` | **SHARED** | Create on login, rotate on refresh, revoke on logout | Dual-token auth with refresh token hashing. |
| `companies` | `Company` | **ADMIN/B2B-ONLY** | Untouched | No driver routes or schema modifications. |
| `admins` | `Admin` | **ADMIN-ONLY** | Untouched | Never accessed by driver app. |
| `invoices` | `Invoice` | **ADMIN/B2B-ONLY** | Untouched | Driver never touches. |
| `notifications` | `Notification` | **ADMIN/B2B-ONLY** | Untouched | Driver does not touch. |
| `company_registration_requests` | `CompanyRegistrationRequest` | **B2B/ADMIN-ONLY** | Untouched | Partner onboarding queue. |

## 5. Schema Changes (Step 4)

1. **`prisma/schema.prisma`**: Added `DriverLocation`, `DriverLocationHistory` models; added `status` + `reason` to `DriverLeave`.
2. **Migration `20261019104000`**:
   - `driver_leaves`: Added `status VARCHAR(20) NOT NULL DEFAULT 'PENDING'` + `reason VARCHAR(500) NULL`; existing rows backfilled to `'APPROVED'`.
   - `driver_locations`: PK `driver_id`, GPS coords + telemetry + `updated_at`.
   - `driver_location_history`: BIGSERIAL PK, `driver_id`, `lat`, `lng`, `speed`, `recorded_at`. Index on `(driver_id, recorded_at)`.
3. **`src/seed.js`**: Seeded test office, company, two drivers (password: `Driver@123`), assigned trip, wallet credit.
